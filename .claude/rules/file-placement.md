# Where files go

## Ask first

Before creating any file, ask **one short question** to confirm the format
(Markdown, Word, or PDF) and the file name, unless the person already said
so in their message. If they said "just do it" or gave the format, don't ask.

## Placement

| What you're making | Where it goes |
|---|---|
| A chapter study guide | `Course Files/Study Guides/<range folder>/` (see below) |
| An explanation of a concept or problem | `Course Files/AI Explanations/` |
| Everything else you generate: analyses, reviews, summaries, plans, drafts, revised or compiled versions of the team's work | `AI Directory/Generated Outputs/` |
| Memory and logs | `AI Directory/MemoryBank.md`, `SessionLog.md`, `Assignments.md` |
| Issues | `Users Directory/Issues/` (both files, see the issue-logging rule) |

Never leave a requested output only in the chat if the person asked for a
file.

**Study guide folders:** the existing folders are `TOGAF Ch1-7`,
`TOGAF Ch8-9`, and `TOGAF Ch10-12`. Put a guide in the folder whose range
contains its chapter. For a chapter outside those ranges, ask which folder
to use or whether to create a new one.

## The team's files are read-only

`Users Directory/Course Assignments/` holds the team's own drafts, notes,
interviews, and submissions. Never edit, move, rename, or delete anything
there unless the person explicitly asks you to. If you revise their work,
save your version in `Generated Outputs` and say which file it's based on.

The same goes for `Course Files/Readings/` and `Course Files/TOGAF Templates/`.

## File names

- **Plain ASCII only.** No ®, ™, en or em dashes, or curly quotes. Use a
  normal hyphen. Special characters get garbled on Windows and in zips.
- Dated outputs: `YYYY-MM-DD - Title.ext`, for example
  `2026-10-16 - Analysis - Proposal Summary.docx`.
- Study guides: `Chapter N - Chapter Title - Study Guide.ext`, matching
  the existing guides.
- Never overwrite an existing output. Save a new version with ` (v2)`,
  ` (v3)` and so on, unless the person asks you to replace it.

## Check your work

After creating a Word or PDF file, confirm it actually opens and that its
text reads correctly before telling the person it's done.
